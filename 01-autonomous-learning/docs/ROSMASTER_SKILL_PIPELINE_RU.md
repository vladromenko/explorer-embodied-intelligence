# Общий offline backend ROSMASTER02/03

`explorer_sim.rosmaster_skill_pipeline` реализует обучение и загрузку двух кандидатов одного полного ROSMASTER с одновременным 9D action contract. Источник показа keyboard/gamepad или SO101 leader хранится в provenance; downstream, SkillSpec, модельные версии и источники оптимизации общие. Отдельных пользовательских arm/base моделей нет. Модуль не открывает hardware/camera/network и не выполняет физику или развёртывание.

## Реализованные кандидаты

1. Официальный компактный LeRobot0.6.1 ACT9. Реальные исходные RGB проходят decode/shape/SHA проверку, resize bilinear и один ImageNet transform. `observation.state` имеет106 координат:53 признака плюс53 validity masks. `action` всегда9 координат исходных names/units. Признаки: буквально записанный prior-command9; доступные joint feedback/commands, odometry position/quaternion, base velocity, IMU,8 LiDAR sectors, metric goal, gripper aperture и4 median-depth tiles. Нельзя склеить joint6+measured odometry в выдуманный prior9. Privileged simulator object truth, true phase label, исходный expert action и evaluator success не входят в actor observation.
2. Hybrid — тот же ACT9 для контакта/согласованного движения, calibrated goal/perception bridge, A* по исходной observed occupancy map с body footprint inflation, body-frame trajectory tracking, обученный по наблюдениям phase prototype classifier, последовательные transitions и recovery guard. Это внутренние компоненты одного ROSMASTER, а не альтернативные embodiment contracts.

Perception использует либо source-bound metric goal с matching calibration/frame, либо locked RGB detection+bbox с настоящим aligned depth и исходными intrinsics/extrinsics. RGB/VLM без метрической геометрии не становится координатами. Nonzero distortion без отдельно квалифицированного undistortion блокируется. Bounding-box depth не доказывает контакт/захват/устойчивость. A* не объявляет unknown cells свободными, требует общую odometry/map/goal frame и source-bound robot geometry/footprint. Пока такой карты или геометрии нет, hybrid возвращает typed blocker; ACT9 baseline остаётся отдельным реализованным кандидатом.

Phase classifier обучается на source phase labels только в train. При inference он получает sensor values/masks и RGB statistics; true phase не передаётся actor или classifier. Transition требует independent phase receipt через trusted server verifier, без него нет full completion. Таймер не превращается в успешный этап или разрешение отпустить предмет. После длительного отсутствия подтверждения требуется measured relocalization/recovery, затем reset policy. Все фазы должны получить отдельные подтверждения. В модуле нет автоматического motor fallback.

## Источники, masks и splits

`CanonicalCorpus(path)` повторно проверяет `explorer_unified_embodied_skill_dataset_v1`, оригинальный envelope, все source SHA и авторитетный `inspect_embodied_episode`. Проверяются единый skill/version/contract, immutable train/development partition, original episode/scene/session/object groups, RGB bytes/frame identity и независимые whole episodes в обоих разделах. Sealed payloads не загружаются в optimizer/evaluator. Неполные/неуспешные source phases не становятся expert targets. Targeted/recovery targets остаются частью общей SkillSpec, а chunk не перескакивает через исключённый промежуток записи.

Normalization state/actions рассчитывается только на train и сохраняется вместе с counts/scales/mean; development не меняет статистику. Missing measurements сохраняются raw null/false mask. Numeric zero в model tensor — только placeholder с явным derived-feature validity, не новая measurement. Настоящие neutral prior9 остаются девятью валидными исходными нулями. Optional channel, не прошедший causal admission, не используется actor; исходные телеметрические masks не переписываются. Power остаётся recorded context и не входит в motor features.

Model manifest и SkillCard разделяют recorded/admitted/model-used channels, valid training counts, ACT9/hybrid входы, feature schema, source/model/implementation SHA, train/dev/sealed IDs и ограничения. Отсутствующий feedback не включается принудительно: command-estimate profile с исходными reference/boot/prior9/native dispatch допускается при масках реального отсутствия. Старый6D или state9 CUDA receipt не квалифицирует новый106D input.

## API для интегратора

- `pipeline_capabilities()` — лёгкий import без Torch/MuJoCo/GPU, job kind `rosmaster_skill_train`, qualified device CPU, размер106/9, implemented candidates и необходимые данные. Наличие реализации не означает наличие пригодных текущих записей или физического навыка.
- `train_pipeline(dataset_manifest, output_dir, settings=None, progress=None)` — actual optimizer, exact resume через существующий maintained ACT helper, save/reload, matched independent development metrics и immutable model artifacts.
- `train_rosmaster_skill(store, job)` — worker adapter. Root владеет enqueue/авторизацией, resource admission, runner и registry. UI должен использовать прежний общий skill/source quality/split guard; обход single clip/частичным контрактом не разрешается.
- `RosmasterSkillPolicy(model_manifest,candidate='ACT9'|'hybrid')` — загрузка checkpoint с SHA/schema106→9, `reset()` на новый episode, `predict(observation,read_payload,verify_observation=trusted_callback,phase_evidence=None,verify_phase_evidence=None)`. Observation не требует target action. Без trusted sensor admission inference блокируется. Возвращает только command data, ничего не отправляет. Hybrid дополнительно требует подтверждённый progress и геометрию. `recover(receipt,verify_evidence=...)` требует measured relocalization.
- `PipelineBlocked` содержит code/detail/episode_id и `.document()`; отсутствие essential prior9, dispatch/source proof, map/geometry, ambiguous phases или recovery evidence имеет разные причины.

Существующий workflow при этом должен переключить permanent implementation stub на фактические capabilities этого backend, сохранив реальные source/data blockers. Текущие старые observation-only captures без causal9D не получают допуск из наличия нового кода. Реальный controller executor, physical authorization, STOP и отдельная проверка исходных настроек остаются обязанностью runtime интегратора.

## Квалификация и пределы

Команда: `pytest tests/test_rosmaster_skill_pipeline.py -q`. Все sources/Store/checkpoints — временные software fixtures; никакой моторной команды, реального сенсора или simulator rollout в тестах нет. Реальный ACT обучается8 CPU optimizer updates, weights меняются, checkpoint перезагружается с max error≤1e-6; saved network реагирует и на RGB, и на fused state. Сохраняются raw loss/gradient/optimizer states, immutable sources, model inputs, matched dev predictions и hybrid traces. Separate tests проверяют masks/neutral9, train-only stats, source tamper, sealed/leakage, actual A*, calibrated depth, phase/recovery guards и lazy control-plane import.

`ROSMASTER_SKILL_PIPELINE_VALIDATION.json` — receipt короткого software fixture run, не H1–H5 science result. Development MAE/phase accuracy не являются learned-policy rollout или mastery. Полное автономное выполнение, независимая физика, long-run learning, реальные sensor/map producers, event receipt adapters, CUDA106D qualification и физическая проверка остаются отдельными незавершёнными этапами. Ни шасси, ни одна рука не движутся без отдельного разрешённого наблюдаемого пользователем теста; исходные настройки контроллеров сохраняются.

## Queued source и code binding

Worker adapter требует server-built `config.skill_workflow`: aggregate SHA, skill/version/spec SHA и точные train/development/sealed original ID sets проверяются до optimizer; источник находится внутри `store.root`. Это дополняет admission root API и блокирует подмену уже поставленного задания. Resume metadata привязана к implementation SHA обоих sensor/hybrid helpers, а загрузка модели отклоняет неподтверждённый feature/hybrid code drift. Normalizer сохраняет явные feature units. ModelCard ID включает конкретный model manifest SHA: повторное обучение с другими weights/кодом не перезаписывает старую версию при неизменных data/settings.

Исторический receipt первоначальных8 updates относится к исходникам `f9a9f6d` (интегрированный source `86e85ae`), source SHA записаны в receipt. Новые provenance headers/guards меняют SHA; повторную квалификацию8 CPU через итоговый queued adapter выполняет root. Исторические checkpoints не повышаются автоматически до нового графа. Быстрые guard/lazy/split/mask/phase проверки не запускают optimizer повторно.
