# Исполненный цикл библиотеки навыков в симуляции

`explorer_sim.skill_cycle.run_skill_cycle(store, job)` проверяет полный программный
маршрут: сохранение модели и карточки → поиск совместимого навыка → настоящее
дообучение → независимое исполнение кандидата → два последовательных этапа →
повторное исполнение сохранённой исходной модели → принятие либо отклонение.
Все движения выполняет MuJoCo. Роботы, ROS и настройки контроллеров не используются.

```python
result = run_skill_cycle(store, {
    "id": "new-skill-cycle-job",
    "config": {
        "source_job_id": "completed-dagger-id",
        "adaptation_steps": 64,
        "seed": 72041,
        "evaluation_episodes": 6,
        "composition_episodes": 2
    }
})
```

Вместо `source_job_id` разрешён явный `source_result` — путь к завершённому
`result.json` DAgger. Вход должен содержать настоящие до/после чекпойнты,
проверенные результаты optimizer/save/reload и исходные typed teacher-query
поправки. Для перемещённых исходников исходный PPO-пилот задаётся через
`pilot_source_result`. CAD задаётся `mesh_dir` или `EXPLORER_SIM_MESH_DIR`.

## Реальные объекты вместо символического плана

Оба исходных ACT-чекпойнта копируются с проверкой SHA в
`store.root/artifacts/skill_library/<content-hash>`. Оригиналы остаются на месте.
Это самостоятельные файлы моделей, а не ссылки на изменяемую память процесса.
Карточки записываются и повторно читаются через настоящую SQLite-таблицу
`Store.skills`. Из совместимых карточек выбирается модель по исходному
development-результату; проверяются задача, CAD-эмбодимент, девять каналов,
единицы, нормализация, RGB preprocessing, файлы и tensor digest. Это обычный
поиск по метаданным, а не обученный семантический поиск.

После поиска отдельно загруженная копия модели выполняет 64 настоящих шага
AdamW через публичный ACT API. Обучающие данные — успешные исходные экспертные
показы и исходные DAgger teacher-query метки. Действия неудачных попыток ученика
не становятся целями BC. Контрфактические метки учителя остаются отдельным
типом данных и не объявляются исполненными восстановительными движениями.
Входы ACT: RGB и оценка команды, без координат цели/реального состояния MuJoCo.

Новый чекпойнт сохраняется, повторно загружается, получает собственную pending
карточку в SQLite и ещё раз извлекается оттуда перед проверкой. После проверки
появляется новая неизменяемая версия карточки: принятая для simulation development
или отклонённая. Физическая готовность всегда остаётся `false`.

Незавершённые попытки остаются в собственных каталогах `attempts/<uuid>`.
Пути чекпойнтов уже сохранённых карточек не перемещаются. Повторный завершённый
вызов проверяет контекст, исходники, артефакты и файлы карточек, не обучает снова.
Возобновление optimizer с середины этого typed раунда пока не заявляется.

## Два этапа без сброса физики

Первый этап исполняет исходный ACT до DAgger; второй — нового дообученного
кандидата. Обе задачи — достижение разных видимых целей одним и тем же CAD-роботом.
Это не захват и не композиция задач с тканью.

Активная MuJoCo-среда сбрасывается один раз в начале всей последовательности.
Для второй цели используется FK отдельного `reference MjData`; активные
положения, скорости, команды и время не сбрасываются. Цель перемещается в сцене
и видна на RGB. До/после перехода битово сравнивается полное
`mjSTATE_INTEGRATION`, сохраняются оба SHA. Сбрасываются только счётчики задачи
`hold/steps/last_distance`, а не физика.

NPZ сохраняет действительные запрошенные и приложенные к симулятору команды,
время и отдельно помеченный evaluator-only qpos. Последняя приложенная команда
этапа 1 обязана совпадать с первой оценкой команды этапа 2; время на границе
также проверяется по сохранённым трассам. Второй этап исполняется даже после
неудачи первого, чтобы измерить оба. Общий успех требует успеха обоих этапов.

## Приёмка и сохранение старого навыка

До проб объявляются новые непересекающиеся development seeds и условия:

- кандидат достигает минимум 4/6 успехов и не уступает исходной извлечённой модели;
- минимум 2/2 полных двухэтапных последовательностей успешны;
- сохранённая исходная модель не теряет успехи при повторном исполнении после
  дообучения кандидата.

Acceptance и retention используют разные свежие seeds; внутри каждой пары
повторяются те же сцены для сравнения. Их наблюдения не входят в обучение.
Отсутствующее измерение не превращается в успешную проверку. Это development-
критерии модели, не новые настройки безопасности робота и не закрытый финальный тест.

Retention проверяет сохранённую версию исходной модели в библиотеке. Это
не эксперимент с забыванием внутри одной перезаписанной сети и не проверка H5.

## Фактический результат

Запуск `1a23e3f18f7d43108a114e22a7127857`, источник
`dagger-cpu-development-tuning480-v1`, 64 новых optimizer updates после поиска.
Начальный seed `72041`; acceptance `82041..82046`, retention `92041..92046`,
композиция `[102041,112041]` и `[102042,112042]`.

| Измерение | Результат |
|---|---:|
| Новые успешные попытки исходной модели | 0/6 |
| Новые успешные попытки кандидата | 0/6 |
| Реальная двухэтапная композиция | 0/2 |
| Повторное исполнение сохранённой модели | 1/6 → 1/6 |
| Решение | кандидат отклонён |

Веса кандидата изменились; официальный save/reload дал max error 0.0. В SQLite
четыре реальные карточки: две исходные, pending и отклонённая версия кандидата.
На обеих границах этапов полное интеграционное состояние сохранилось, сброс
активной физики отсутствовал. Условия после результатов не ослаблялись.

29 целевых тестов прошли; один существующий explicit pilot integration test
пропущен. Полный цикл выше выполнен отдельно с реальными моделями/оптимизатором.
Точные результаты и SHA находятся в `SKILL_CYCLE_VALIDATION.json`. Модели,
трассы и SQLite snapshot через backup API дополнительно сохранены приватно в
`_registry/private/engineering_runs/skill-cycle-20261026` с проверкой 54 файлов.
Пути внутри исходных метаданных сохранены; при переносе нужен обычный mapping
исходного корня из `preservation.json`.

Torch 2.14.1 / torchvision 0.29.1 данного Mac-runtime выходят за объявленные
границы LeRobot 0.6.1. Проверено конкретное выполнение, а не всё окружение.
Закрытого теста, физических проб, надёжного восстановления, новой научной
методики или успеха с одеждой здесь не установлено.
