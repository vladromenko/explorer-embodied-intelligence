# Программная трасса двухэтапной симуляции

`explorer_sim.program_trace.export_program_trace(source_result_path, target_dir)`
читает завершённый skill cycle и создаёт компактную привязку программы к его
действительным кадрам и командам. Идея взята из **AW-0, CODE_ANNOTATION, Route B:
task program**: узкая задача описана фиксированными примитивами, а строки
программы привязаны к порядку исполнения. Первичный документ зафиксирован на
[7ad228bebb897bf01705cc10171e1d88cf5e9b22](https://github.com/ZhuoyangLiu2005/agentic-wam/blob/7ad228bebb897bf01705cc10171e1d88cf5e9b22/docs/CODE_ANNOTATION.md),
SHA-256 `34c44a5f90cc3d829b4dfbb812cab2074746f78d962c228636f2fd842b988424`.

Программа — два объявления `reach_visible_target`, с ID библиотечного навыка,
хешами чекпойнта, версией библиотеки и исполнителя. Это JSON-описание уже
исполненного проверенного маршрута. Исходный skill cycle не записывал такой
JSON до попыток: поле `source_program_predeclared=false` сохраняет это различие.
Описание не исполняется и не является запуском модели AW-0.

## Файлы экспорта

- `program.json` — две строки декларативной программы и связи с моделями;
- `trace.jsonl` — одна запись на каждый настоящий source RGB/action row;
- `events.json` — отдельные события смены цели из журнала симулятора;
- `episode_order.json` — явный порядок эпизодов, этапов и исходных строк;
- `receipt.json` — источники, версии, SHA, область использования и счётчики.

Трасса сохраняет запрошенную нормированную команду и действительно приложенную
к симулятору команду отдельно. Командная оценка не переименовывается в измеренную
позу. RGB обозначен SHA своих исходных байтов; визуальные описания, детекции и
оценки предметов не генерируются. Время остаётся временем MuJoCo внутри каждого
эпизода; глобальный номер строки не объявляется глобальными физическими часами.

Проверяются SHA источников, число/форма всех массивов, одна команда на кадр,
причинность соседних команд/времён и непрерывность двух этапов. Декодируются
именно байты NPZ, чей SHA проверен. Оригиналы не перезаписываются и повторно
сверяются после экспорта. Готовый экспорт публикуется атомарным переименованием;
повторный вызов проверяет источник, версию экспортёра и все выходные хеши.

Привязка этапа 1 к исходной модели, этапа 2 к pending-кандидату разрешена только
для точного замороженного исполнителя с SHA
`b0776fa90b734d703df0841eb7c0919986bf88da301f28e2fca67aee49d6dd64`
и полного соответствующего библиотечного binding. При неизвестной версии или
недостающей связи строка программы/фаза остаётся `null`, `label_valid=false`.
Неизвестные исходы и причина завершения не восстанавливаются догадкой.

Смена цели явно помечена `evaluator_assisted_sim_executor_event`. Это помощь
оценщика симуляции, а не визуально предсказанное событие. Неуспех предыдущего
этапа сохраняется; переход не выдаётся за подтверждённое достижение цели.

## Граница использования

Все новые labels и события — **offline targets / анализ**. Они не становятся
входами действующего ACT, не дают ему будущие события/истинную будущую фазу или
привилегированную координату цели. Актор остаётся с прежними RGB и оценкой команды.
Нет нейронной памяти, оптимизатора, обучения классификатора фаз, импорта AW-0,
загрузки весов, обращения к устройствам или отправки изображений.

Это собственный JSON sidecar. Авторский `policy_code_idx_*.pt`, преобразование
в unified64-D SFT и запуск AW training не заявляются. До добавления памяти нужно
отдельно различить слабый примитив и потерю плана; существующие провалы reach
этого различия не устанавливают.

## Минимальная отдельная задача

Root создаёт отдельный CPU/data job `program_trace` с завершённым
`config.source_job_id` вида `skill_cycle`. После проверки статуса и типа:

```python
receipt = export_program_trace(
    store.root / "jobs" / source_job_id / "result.json",
    store.root / "jobs" / trace_job_id / "program_trace",
)
```

`target_dir` — новый отдельный подкаталог, поскольку каталог задачи уже может
содержать worker-log. Оригинальный `result.json` skill cycle остаётся неизменным:
receipt принадлежит отдельной задаче. Дополнительно есть helper
`export_skill_cycle_trace(store, source_job_id)` для завершённой задачи, который
пишет в `artifacts/program_traces/<source_job_id>`.

4 этапа, 2 эпизода**, оба исхода `false`. События перехода — позиции 60 и 180
в общем порядке; источники кадров, команд и меток проверены. Повторный экспорт
вернул прежний receipt без изменения файлов.
