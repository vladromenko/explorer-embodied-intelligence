# Визуальный ACT на полной задаче с предметом

`explorer_sim.manipulation_student:run_manipulation_student(store, job)` — отдельный
job `manipulation_student` с CPU или отдельно проверенным CUDA backend. Он не подменяет существующий privileged PPO-пилот:
источник показов здесь явно называется `scripted_truth_IK_not_PPO_not_learned`.
Поддерживаются `candy_to_tray` и деформируемый `sock_to_basket` из реальной
MuJoCo/CAD-сцены. База в симуляции закреплена; физического I/O нет.

Каждый исходный показ выполняет approach → descend → close → lift → carry →
place → release → withdraw → settle через конечные управляющие команды и
реальные контакты на каждом физическом подшаге. В экспертный набор попадает
только полный успех независимого contact evaluator с точным повторным исполнением
из `mjSTATE_INTEGRATION` (ошибка полного состояния < 1e-9). Неудачные показы
сохраняются в `demonstrations/` и остаются аналитическими данными, а не BC-targets.

Официальный LeRobot ACT 0.6.1 обучается по RGB и **предшествующей** 9D-командной
оценке состояния. Суставные скорости, объектные координаты, целевые координаты,
contact flags, фаза сценария и privileged PPO observation в actor не передаются.
Модель предсказывает конечные команды. В этой неподвижной сцене выполняются только
шесть координат руки; три предсказанные координаты базы сохраняются в raw trace и
не исполняются. Оригинальные параметры контроллера ROSMASTER не читаются для записи
и не изменяются; конфигурация динамики здесь является оценкой симуляции.

Градиенты, оптимизатор, RNG и cursor выборки сохраняет существующий проверенный
`student.optimize_act`. После сохранения выполняется официальный reload с
сравнением action chunks. Официальная пара identity processors сохраняется в
checkpoint и реально исполняется при последующей policy inference; явный
Explorer adapter задаёт ImageNet RGB и fixed-range normalization. Нормализаторы
не оцениваются по проверочным сценам.

Ученик затем исполняется замкнуто в MuJoCo по новым RGB-кадрам и собственной
предшествующей команде. Проверочные seeds `seed + 10000 …` отделены от seeds
показов `seed … seed + demonstration_episodes - 1`; это development split,
а не закрытый финальный тест. Для каждой попытки сохранены исходный RGB,
raw predicted endpoint9 до ограничения, фактически запрошенные и исполненные
arm endpoints, исходное/последующие полные состояния и contact substep trace.
Независимый evaluator требует захват, подъём, перенос над целью, отпускание,
поддержку дна и оседание. Train loss не используется как успех задачи.

`frame.jpg` и `frame.json` в папке job содержат последний фактически рассчитанный
кадр, stage, simulation time и `actual_workers=1`. Во время optimizer updates
это подписанный последний кадр завершённого scripted baseline. Визуальные
rollouts обновляют его каждые десять исполненных действий и при завершении попытки.
Не рисуются фиктивные parallel workers.

Пример конфигурации:

```json
{
  "task": "candy_to_tray",
  "seed": 321041,
  "demonstration_episodes": 3,
  "act_steps": 120,
  "batch_size": 8,
  "chunk_size": 16,
  "image_size": 64,
  "evaluation_episodes": 2,
  "horizon": 700,
  "device": "cpu"
}
```

Все числовые параметры строго целые; bool не принимается. Для `device=cuda` нужен отдельно квалифицированный GPU interpreter и совпадающая
квитанция compact ACT backend; policy, check batch и сохранённые processors
действительно переводятся на выбранное устройство. Девятиосевой маршрут отдельно
проверен фактическими обновлениями и замкнутым rollout: см.
`MANIPULATION_CUDA_VALIDATION.json`. В используемом wheel есть явное предупреждение
PyTorch о CC8.7 и несовпадении заявленных верхних границ LeRobot; успешная
квалификация ограничена реально исполненными операциями, а не любым CUDA стеком. `horizon` ограничивает независимую попытку
ученика; scripted baseline сохраняет полную последовательность до конца.
Полная кухонная навигация этим job не реализуется.

В папке job сохраняются `visual-manipulation-provenance.json`,
`visual-manipulation-model.xml`, `demonstrations/`, `dataset/`,
`act_resume/`, `student_act/`, `development/` и
`visual-manipulation-result.json`. Контрольные SHA связывают исходники, CAD,
показы, нормализацию, checkpoint и независимые попытки. Повторный вызов завершённого
job проверяет целостность артефактов. Прерванные генерации и попытки остаются в
архивных подпапках. Один file lock исключает двух владельцев одного job.

Даже `trained_and_development_evaluated` не означает, что предметный навык освоен.
Короткий запуск может дать 0 успешных попыток; такой отрицательный результат
должен остаться видимым. Ни физический успех, ни новизна H1–H5 здесь не заявляются.

GPU-квитанция для планировщика: `~/.local/share/explorer/state/qualification/
manipulation-act9-cuda-20261026/qualification.json`. Реально пройдены 11 тестов без
пропусков; восемь optimizer updates на `cuda:0` заняли около 3,02 с, reload error
0,0, сохранённые processors исполнены. Это короткая 32-шаговая проверка интерфейса
и динамики, а не полный GPU-тест предметного навыка. Сравнение скорости с другим
CPU-бюджетом/размером изображения этим измерением не устанавливается.
