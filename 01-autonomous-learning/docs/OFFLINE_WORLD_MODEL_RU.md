# Прогноз следующего наблюдения по действию

`explorer_sim.world_model` — явно **ENGINEERING_GLUE**, компактный проверочный
baseline на PyTorch. Он читает существующие NPZ, обучает прогноз следующего RGB
и состояния, проверяет сохранение весов/оптимизатора и сравнивает ошибки на
отдельных эпизодах. Контроллеры, камеру, симулятор и обученную политику он не
запускает. Веса не объявляются новым навыком и не добавляются в библиотеку навыков.
H1–H5 и успех физических заданий остаются непроверенными.

## Вход и граница времени

Используются те же `explorer_npz_episode_v1` / `explorer_robot_episode_v1` и
`dataset_export.load_episode`, что и в существующем импорте. Нужны RGB, состояние,
команда, названия координат, единицы и конечные диапазоны нормализации. Состояние
и действие должны иметь совпадающие координаты и единицы исходного контракта.
`state_native` и `action_native` сохраняют исходные единицы; для прежних девятиосевых
данных используются `state_command9` / `command9` либо обратное преобразование
записанного нормализованного состояния. Последнее является оценкой команды,
**не измерением положения**. `evaluator_goal_xyz` в модель не поступает.

Один пример строго разделён: вход `(RGB_t, state_t, action_t)`, цель
`(RGB_{t+1}, state_{t+1})`. Последняя строка эпизода не образует пример, переходы
через границы эпизодов запрещены. Для физических данных требуются исходные метки
времени; будущий кадр должен быть строго после текущего действия, а метка состояния
не раньше него. Повторённый старый кадр на более поздней сетке ресемплинга не
считается будущим наблюдением. Такие переходы исключаются со счётчиком.
Заявленные часы источника не подтверждают самостоятельно время экспозиции или
калибровку часов. У старого сохранённого симуляционного набора без меток остаётся
честная область `index_order_only_no_native_timestamps`.

Неуспешные эпизоды могут обучать динамике. Их исходный outcome сохраняется;
они не становятся успешными экспертными примерами для ACT.

## Интеграция

Точка входа: `run_world_model(store, job)`. `store` предоставляет только `root`
и `update_job(id, progress=..., result=...)`. Регистрацию вида задания, ограничения
планировщика и пользовательскую форму подключает control-center отдельно.
Этот модуль не меняет `app`, `job_runner`, `scheduler`, ACT или экспорт набора.

Пример `job.config`:

```json
{
  "dataset_manifest": "/absolute/path/dataset/manifest.json",
  "development_episode_ids": ["episode_0009", "episode_0010", "episode_0011"],
  "optimizer_steps": 120,
  "batch_size": 8,
  "image_size": 32,
  "device": "cpu",
  "seed": 41
}
```

Если источник уже содержит development, список можно опустить. Если все эпизоды
помечены train/imitation_train, отдельные development выбираются явно до обучения;
исходный manifest не переписывается. `training_episode_ids` необязателен: по
умолчанию берутся остальные разрешённые train. Sealed/test запрещены и для fit,
и для этой development-проверки; established development не становится train.
Проверяются пересечения ID, SHA, исходных кадров и объявленных source-session.
Если session неизвестна, её независимость не объявляется проверенной.

Артефакты находятся в `store.root/jobs/<id>/offline-world-model-<attempt>/`:
два `model.pt`, два `optimizer.pt`, конфигурации, все пошаговые losses,
provenance, evaluation и сравнительный PNG. `result.json` содержит SHA всех
артефактов и источников, IDs/эффективные и исходные split, runtime и область
каждой метрики. Повтор готового задания проверяет SHA и возвращает прежний
результат; изменение источников, параметров или реализации требует нового ID.
Незавершённые попытки сохраняются отдельно. Корректная integration-среда
запускает один worker на ID задания.

`load_predictor(checkpoint_directory, device="cpu")` загружает модель. Её forward
принимает batch `rgb` NCHW float [0,1], `state` и `action` в исходных единицах;
возвращает `next_rgb`, `next_state`. Это прогноз, не разрешение на управление.

## Сравнения и границы

Две сети имеют одинаковую архитектуру/54 916 параметров при девяти координатах,
одинаковые начальные веса и последовательность minibatch. Action-agnostic
получает нулевой action-вектор. Residual CNN/MLP предсказывает реальные следующие
пиксели и native-state; loss равен pixel MSE плюс state MSE, нормализованная
фиксированными диапазонами источника. Adam: lr=0.001. RGB-прогноз ограничен
остаточной поправкой ±0.1 на канал и не является полноценной генеративной моделью.
Изображение приводится к 16/32/64 bilinear, без внешних весов/загрузок моделей.

Persistence сохраняет текущие RGB/state. При `command_estimate` дополнительно
проверяется копирование команды в следующее состояние с сохранением RGB.
Этот baseline выявляет тривиальную связь меток команд вместо физики.
Выдаются RGB MSE/MAE [0,1], нормализованная state MSE и MAE по каждой координате
в собственных единицах. Среднее по переходам и равновесное среднее по эпизодам
показываются отдельно. Смешивать градусы, м/с и рад/с в «среднюю native-ошибку»
или объявлять ошибки вероятностью успеха нельзя.

Первый реальный запуск описан в
`research/experiments/offline-world-model-20261026/VALIDATION.md`.
На нём сохранение текущего кадра оказалось лучше обеих сетей по RGB MSE;
равновесная ошибка состояния также лучше у persistence. Преимущество модели
мира, причинное влияние действий и работоспособность на реальном роботе
этот опыт не подтверждает.
