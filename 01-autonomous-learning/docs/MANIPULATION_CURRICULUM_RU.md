# Контактный эксперт → BC actor → настоящий PPO

`explorer_sim.manipulation_curriculum` добавляет отдельный baseline
**BC-warmstarted privileged SB3 PPO**. Он не переименовывает скрипт в PPO и не
выдаёт привилегированное состояние MuJoCo за вход визуального ученика.

Сначала неизменённый `scripted_actions` выполняется в настоящей CAD-сцене
`ManipulationEnv`: конфета→лоток или свободно деформируемый носок→корзина. По
каждой попытке сохраняются полный независимый contact evaluator, фактические
действия, первоначальные запросы, наблюдения 36D, native integration state,
время симуляции, фаза и настоящие кадры MuJoCo, уменьшенные до 64×64. Неудачные экспертные попытки
сохраняются, но не становятся положительными BC-targets.

Учебная метка — **фактическое изменение командной конечной точки**, делённое на
неизменённые параметры `velocity * period` симуляционного исполнителя. Исходный
запрос может быть больше допустимого шага и записывается отдельно. Длинный
подход не подавляет короткое отпускание: сумма весов каждой реально
наблюдавшейся экспертной фазы одинакова. Исходное фазовое
происхождение каждой строки сохраняется в неизменяемом NPZ; sampling задан
сохранённым seed.

Из статистики только train-показов сохраняется нормализация привилегированных
наблюдений. Она включена в SB3 checkpoint через собственный небольшой
`BaseFeaturesExtractor`; matching preprocessing не угадывается при загрузке.
Actor mean обучается настоящим Adam по dispatch-targets; critic в этой фазе не
меняется. Число optimizer steps, loss и изменённые имена параметров сохранены.

BC checkpoint сохраняется как отдельный неизменяемый incumbent. Из его копии
запускается настоящий maintained SB3 PPO с rollout/gradient updates и своими
сырыми sampled actions до clipping. Во время PPO и независимых learned rollouts
скрипт не вызывается. Лог стандартного отклонения — гиперпараметр только
симулируемого PPO; параметры физических контроллеров не затрагиваются.

Train и development seeds фиксируются до записи эксперта и не пересекаются.
BC и BC+PPO выполняются на одинаковых development-сценах с отдельными исходами
захвата, подъёма, переноса, отпускания и устойчивого размещения. Проверяются
загрузка checkpoints и точное native-state replay. Кандидат принимается только
при полном успехе всей текущей development-серии без ухудшения incumbent;
неудача остаётся неудачей независимо от BC-loss или частичного подъёма предмета.
Это инженерный pilot gate, а не доказательство обобщения или mastery.

## Запуск интегратором

Backend kind `manipulation_curriculum`, project `01`, CPU:

```python
from explorer_sim.manipulation_curriculum import run_manipulation_curriculum
result = run_manipulation_curriculum(store, job, config)
```

Конфигурация: `task`, `seed`, `demonstration_episodes`, `bc_steps`, `ppo_steps`,
`evaluation_episodes`, `horizon`, `device=cpu`. По умолчанию три экспертных
train-показа, 2000 BC steps, 2048 настоящих PPO timesteps и две development-сцены.
Число actual PPO timesteps сохраняется отдельно: SB3 завершает полный rollout
batch. Используется один CPU thread и один настоящий физический sim worker.

Все попытки сохраняются в `jobs/<id>/attempts/`. При перезапуске после прерывания
создаётся отдельная новая попытка; точное update-level продолжение PPO после
reboot этим модулем не заявляется. Завершённый результат связан с исходниками,
CAD SHA, версиями MuJoCo/SB3/PyTorch и исходными данными.

## Пределы

Это локальная задача с неподвижной базой и привилегированным teacher. Полная
мобильная кухня, физические параметры контакта, визуальный ACT-student,
перенос на ROSMASTER, обобщение по предметам и гипотезы H1–H5 проверяются
отдельно. Даже положительная короткая серия не означает освоение задачи.


## Фактически выполненный первый пилот

Homebrain run `97b6bc8af5834472a8b4fcd590db6f08`, 364,3 с, один CPU thread.
Три train-показа скрипта (seeds 8421–8423) завершили полную задачу конфета→лоток:
по 448 настоящих команд, всего 1344 BC-targets. Development seeds 18421 и 18422
не использовались при BC. BC2000 уменьшил supervised loss с 0,0671 до 0,000290.

Обе BC-попытки достигли независимых критериев захвата, подъёма и переноса над
целью. Полное размещение осталось **0/2**: в конце предмет лежал вне лотка,
контакт с дном отсутствовал. Временный перенос над целью не повышает итоговую
метку. Траектории показывают также raw network outputs вне [-1,1]; исходные
действия до clipping сохранены.

Далее выполнены 2048 настоящих PPO timesteps, 96 optimizer steps / 48 epochs.
Веса изменились. Загрузка checkpoint дала нулевую разницу действий. Кандидат
регрессировал: захват, подъём и перенос 0/2, полная задача 0/2. Он **отклонён**;
неизменённый BC incumbent сохранён. Повторное исполнение 600 запросов из
сохранённого native state дало max error 0,0.

Наблюдаемые стадии отказа установлены по подшаговым контактам и положениям
предмета. Какая именно причина вызвала регрессию PPO, этот пилот не установил.
Слабый learning objective, распределение посещённых состояний и устойчивость
BC требуют отдельных контролируемых проверок. Нельзя объяснять их одним
маленьким train loss или выдавать за освоение полной задачи.

Краткий receipt: `MANIPULATION_CURRICULUM_VALIDATION.json`. Полные NPZ,
подшаговые контакты, RGB, исходники, loss, sampled/clipped actions, оба
checkpoints и SHA находятся по указанному в receipt пути.
