# Сервис наблюдения Explorer на Pi и Nano

Модуль `explorer_shared.node_agent` предоставляет API из
`shared/contracts/API_V1.md`. На Nano он проксирует явно запрошенные штатные операции через существующий
HTTP-контроллер, читает данные и сохраняет наблюдения без прямого ROS/serial
или записи настроек контроллера. На Pi дополнительная станция SO-101 использует
подтверждённые исходные калибровки, читает шины и выполняет отдельно разрешённые
операционные команды положения/torque. Параметры калибровки и привода не меняются.
Этот каталог содержит инструкции; установка и запуск выполняются интегратором.

## Raspberry Pi

Один процесс читает C920 по стабильному пути
`/dev/v4l/by-id/usb-046d_HD_Pro_Webcam_C920_D4EA612F-video-index0`.
Все preview, snapshots, запись и Hailo используют этот источник. Между
процессами Explorer захват защищён файловой блокировкой. Поток MJPEG ограничен
тремя клиентами, 10 кадрами/с и пятью минутами на соединение.

```sh
PYTHONPATH=/path/to/release/shared python3 -m explorer_shared.node_agent \
  --mode pi --node-id pi --port 8091 --state-dir /home/vlados/explorer-node-data
```

Секреты передаются средой доверенного launcher:
`EXPLORER_NODE_TOKEN` (не менее 16 символов), `EXPLORER_INGEST_TOKEN` и
`EXPLORER_CENTRAL_URL`. Не помещайте реальные токены в Git или командную строку.
Все API, кроме минимального `/health`, требуют `Authorization: Bearer …`.
Прямые HTTP-запросы предполагают доверенную локальную сеть; удалённый доступ
организуется через VPN или SSH. UI обращается через сервер NX.

Hailo запускается отдельным worker, по умолчанию 2 inference/с, максимум 5.
Используется H10-совместимый COCO NMS HEF; event rate ограничен одним событием
за пять секунд, heartbeat — раз в 30 секунд. Недоступность модели не блокирует
захват камеры. События содержат модель/hash, frame ID, latency, confidence и
метку `vision_estimate`. Наличие объекта не подтверждает физический захват.
VLM, распознавание лиц и аудио не реализуются этим сервисом.

Два USB-контроллера перечисляются через `/dev/serial/by-id` без открытия
устройств. При отсутствии проверенного `arms.json` роли остаются `unassigned`. На текущем Pi
роли обеих SO-101 подтверждены, исходные калибровки сверены, измерения читаются
около30Гц; реализация — `so101_station.py`. Калибровки
можно перечислить через повторяемый `--calibration-dir`; JSON получает hash,
но не объявляется совместимым с подключённым оборудованием без проверки.

## Jetson Nano

```sh
PYTHONPATH=/path/to/release/shared python3 -m explorer_shared.node_agent \
  --mode nano --node-id nano --port 8092 --state-dir /home/vlad/explorer-node-data \
  --legacy-dir /home/vlad/Explorer/data --no-hailo
```

Nano читает существующие `frame-raw.jpg` и `status.json`, не меняя их.
Он не открывает камеры и не импортирует действующий контроллер. Кадры старше
двух секунд недоступны; status старше пяти секунд отмечается устаревшим.
`nano-rgbd` обозначает фактический legacy-источник с неподтверждённой аппаратной
идентичностью. `nano-logitech` честно недоступен, пока второй источник не найден.
Один legacy-кадр никогда не показывается как две независимые камеры.

## Запись и восстановление

`POST /recordings` принимает `camera_id`, `duration_s` (до 300 секунд),
`recording_id` и необязательный `project_id`. Одновременно допускается одна
запись. Это наблюдение камеры: manifest прямо отмечает отсутствие команд и
измерений суставов. По умолчанию сохраняется до пяти JPEG/с; каждый файл имеет
hash и временные метки. Результат — `manifest.json` и `recording.tar` с кадрами.
Доступны `/recordings/{id}`, `/manifest`, `/download`.

Максимальный объём кадров одной записи — 1 GiB. Запись не начинается при
остатке менее 256 MiB. Frame manifest обновляется с fsync по мере записи.
После перезапуска незавершённая запись становится `interrupted`, кадры
сохраняются; автоматического возобновления действий нет.

Время Pi — оценка получения кадра, а не аппаратная метка экспозиции. Для Nano
это оценка по времени изменения legacy-файла. UTC, monotonic, clock domain,
неопределённость происхождения и frame ID сохраняются явно.

События сначала попадают в общий SQLite `EventOutbox`. Подтверждение NX удаляет
их из очереди; неудачная отправка повторяется с прежним event ID. Фото и видео
в event JSON не передаются. Локальные исходники после отправки не удаляются.
Копирование крупных архивов и резервное копирование организует интегратор.

Проверка без оборудования:

```sh
PYTHONPATH=shared python3 -m unittest discover -s shared/perception/tests -v
```

Новый `mobile_capture.py` на Nano пишет только собственный журнал камеры/датчиков,
независимый от уровня заряда и наличия оценки углов. Прошедшие проверку исходники
старого контроллера/его конфигурация не переписываются.
