# Калибровка переноса: сохранённый backend

Семантический владелец `cross_embodiment_transfer` (новая нумерация 06), исходный `so101_source_learning` (04). Нумерацию новых событий определяет общий semantic registry; прежние документы и измерения не переписываются.

`explorer.transfer_calibration.create_session(store, body, audit=...)` принимает общий UUID навыка, source_version, возрастающий target_version и domain. `session(store, wizard_id)` восстанавливает шаги, revision и сохранённые кадры. `capture_view(..., expected_revision, request_id, capture_provider, measurement_provider, clicks)` читает уже имеющийся серверный кэш; браузер передаёт только клики, а метрическую геометрию вычисляет доверенный провайдер. `solve_step(..., source_coordinates, source_chain)` сохраняет численную калибровку с ID/SHA и немедленно выдаёт её в session.artifact для следующего задания. Ни один API не подключается к устройствам, не отправляет команды и не меняет исходную калибровку.

Шаги: шесть разнообразных поз SO101 с двумя независимыми проверочными видами; по три метрических вида апертуры каждого захвата; объект и цель обеих сцен. Ревизия не даёт прикрепить поздний результат к чужому шагу. Забракованные исходные кадры сохраняются с причинами и счётчиком retry, одинаковый кадр не увеличивает покрытие. Разные clock/boot и неизвестная метрическая геометрия требуют исправления провайдера, а не выдуманных координат.

Пять тестов используют только синтетические позы/изображения и временную SQLite: независимые проверочные позы, ограничения апертуры, метрическая регистрация, durable/idempotent capture с rejected-frame retention и гонкой ревизии, запрет физической квалификации из SIM. Физические измерения, браузерные маршруты/панель, реальный квалифицированный SO101 object policy и target dataset/student pipeline ещё не завершены этим коммитом.
