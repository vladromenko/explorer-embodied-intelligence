# Модель навыка02: обучение и проверка

Откройте `/experiments/02`, выберите подтверждённый навык и точную версию.
После завершения записи отдельно просмотрите исходные кадры, исход/фазы и
одобрите перенос. Ошибки передачи доступны в общей очереди; повтор сохраняет
историю и проверяет исходный SHA. Неудачные/неполные/неясные показы остаются
для анализа. Технические наблюдения без экспертных команд не обучают модель.

Панель показывает охват условий, train/DEV/sealed и следующий нужный показ.
Начальные3–5 показов — проверка тракта; качество и покрытие определяют дальнейший
объём. Для начального допуска нужны разные учебные варианты и отдельные DEV/
закрытые сессии. Один и тот же предмет/сцена/session не переносятся между splits.

1. После допуска выберите число шагов и нажмите «Обучить общий навык ROSMASTER».
   Используется компактный CPU-профиль, проверенный с официальным LeRobotDataset.
   Бюджет шагов не обещает освоения задачи. Прогресс, журнал, пауза, продолжение,
   отмена и ошибки доступны в карточке задания и общей очереди.
2. Выберите сохранённую модель именно этой версии навыка. Видны число реальных
   optimizer updates, проверка save/reload и SHA модели, checkpoint и aggregate.
   Новые показы/версии не меняют сохранённые модели задним числом.
3. «Проверить на DEV» создаёт отдельный CPU worker без optimizer, оборудования
   или закрытых payloads. MAE приведена отдельно для каждой команды в её единицах;
   эта ошибка не является процентом полного успеха задачи.
4. «Shadow на живом наблюдении» загружает модель, затем читает свежие исходные
   наблюдения Nano и предсказывает полную9D-команду. Ни одна команда движения
   не отправляется. Неподтверждённый native reference, устаревший кадр, неверный
   SHA/clock, неизвестный prior или несовместимые сенсоры останавливают проверку.
5. Физическое испытание проводится отдельно владельцем по
   [checklist](../../PHYSICAL_CHECKLIST.md). Ни train, ни DEV, ни shadow не
   выдают разрешение на движение. Шасси остаётся запрещённым.

Проверки официального Dataset/ACT и настоящей очереди описаны в
[QUEUED_NATIVE9_QUALIFICATION_RU.md](QUEUED_NATIVE9_QUALIFICATION_RU.md).
Там исходные показы сгенерированы программно, а optimizer, новые процессы,
checkpoint и DEV вычислены по-настоящему. Реальные успешные показы и физический
навык этим не подтверждены. Актуальный live release смотрите в STATUS.
