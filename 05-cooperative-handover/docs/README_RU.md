# 05 · Проверяемый протокол передачи предмета

Одна FSM в `shared/explorer_shared/handover.py`:

`PREPARE → ROSMASTER_HOLDING → OFFER → SO101_APPROACH → RECEIVER_GRASP_CHECK → RELEASE_AUTHORIZED → RELEASE → CONFIRM_TRANSFER → SO101_FINISH`.

Закрытие принимающего захвата **не** разрешает отпускание. Требуется независимое свидетельство удержания принимающей стороной либо явное подтверждение оператора. Команда суставу, VLM-текст и таймер таким свидетельством не являются. При отсутствии подходящих датчиков используется операторское подтверждение, не подменяемое измерением силы.

В `HoldEvidence` отдельно записаны acquisition clock устройства и receipt clock координатора. Срок годности оценивается только в явно совпадающем локальном receipt clock domain. Несовпадающие monotonic clocks не сравниваются. Свидетельство связано с конкретным object_id и операционным statement.

Потеря связи, STOP, истечение разрешённого времени фазы и относительное движение при совместном удержании переводят FSM в `SAFE_STOP`, не раскрывая захват. После STOP требуется явный reset: старые подтверждения не возобновляют последовательность. Идемпотентные IDs не допускают повторных переходов; конфликтующий payload отклоняется.

`handover_test` выполняет детерминированные тесты переходов, сохраняя `handover_trace.json`. Виртуальные test-oracles допускаются только в виртуальном режиме и отвергаются физическим режимом. Это **тест протокола**, не динамическая симуляция контакта и не физическая передача. Вывод не содержит доказательства physical success.

Для физического соединения с существующими исполнителями интегратор предоставляет реальные события обеих сторон. Этот модуль не открывает приводы и не изменяет настройки контроллеров. FSM — ENGINEERING_GLUE, не новая научная идея; provenance ID `HANDOVER_VERIFIED_FSM`.
