## 1. Назначение и границы

Лаборатория закрывает локальный imitation-learning цикл для двух SO-101:

1. человек двигает leader;
2. follower повторяет движения по сохранённой калибровке;
3. wrist/top RGB, фактическое состояние follower и отправленные action сохраняются;
4. данные проверяются, при необходимости размечаются SAM3 и экспортируются;
5. ACT либо SmolVLA обучается локально на Jetson;
6. checkpoint сначала загружается без движения;
7. отдельный явный Start запускает политику на follower.

Это не геометрический planner Wristlab и не универсальный робот по текстовой
команде. ACT не использует текст задачи. SmolVLA принимает текст, но качество всё
равно определяется покрытием демонстраций.

## 3. Архитектура текущей реализации

### 3.1. Сервер и интерфейс

`src/so101_lab/app.py` соединяет REST/WebSocket API с менеджерами записи,
предпросмотра, телеоперации и задач. `static/` содержит единый русскоязычный
Studio UI: камеры, запись, библиотеку датасетов, обучение, checkpoints и запуск.

API различает camera-only preview, calibrated teleoperation без записи, запись
эпизода, фоновые jobs, проверку checkpoint без движения и физический запуск
только обученной политики. Технический replay через публичный API отключён:
`execution_mode` должен быть `learned`.

### 3.2. Владение аппаратурой

`resources.py`, process locks и общий `hardware_control_lock` не допускают
одновременное открытие устройства несколькими собственными задачами. Перед
физическим Start проверяются владельцы follower и wrist-камеры, доступная память
и compute conflicts. Собственный preview освобождает wrist-камеру перед rollout,
поэтому приложение не блокирует само себя.

STOP увеличивает generation-счётчик и прекращает новые команды. Задача,
подготовленная до STOP, не может тихо начать движение после него.

### 3.3. Камеры и телеоперация

`hardware.py` реализует постоянный `CameraCapture` с последним кадром и
монотонным timestamp. Preview и запись используют одного владельца камер.
`teleoperation.py` повторяет leader → follower через штатные LeRobot-конфиги и
локальные calibration snapshots; новая произвольная математика суставов не
вводилась.

Доступны режимы `two_cameras` и `wrist_only`. В wrist-only режиме top не
сохраняется, не используется обучением и скрыт в UI.

### 3.4. Raw-запись

`recording.py` хранит каждый эпизод отдельно:

```text
data/ds_<id>/
  dataset.json
  episodes/<episode-id>/
    episode.json
    frames.jsonl
    wrist/*.png
    top/*.png                 только для two_cameras
    annotations/sam3-v1/      если разметка выполнена
  quarantine/<episode-id>/    прерванные и заменённые записи
```

Для каждого наблюдения фиксируются causal frame ID и timestamp камеры, возраст
кадра относительно motor sample, позиции шести суставов, action, действительно
отправленная follower, пути/хэши изображений, источник и calibration provenance.

Lossless PNG пишутся отдельным bounded writer. Compression level 1 уменьшил
реальный поток примерно с 26 до 10 МБ/с без изменения декодированных RGB.
`fsync` убран из 30 FPS контура и выполняется на границе эпизода. Очередь
вмещает полный текущий 18-секундный wrist-only эпизод.

STOP вызывает abort: незавершённая запись остаётся в quarantine. Только
«Сохранить эпизод» делает её частью train-датасета. Целевое число эпизодов
хранится в metadata, поэтому продолжение начинается с фактического прогресса.

### 3.5. SAM3

`annotations.py` запускает локальный SAM3 на сохранённых изображениях и пишет
маски, bounding boxes, category/color, score, причинные track IDs и provenance.
Разметка проверяет соответствие исходному кадру по timestamp/hash.

SAM3 не выполняется в motor loop. Автоматическая полная разметка начинается
только после достижения целевого числа эпизодов, чтобы промежуточная annotate
job не удерживала lease и не блокировала продолжение записи.

RGB-маска не даёт надёжную 3D-координату без подтверждённой геометрии. Код не
объявляет неизвестный XYZ измеренным.

### 3.6. Валидация и LeRobot export

`lerobot_export.py` проверяет timestamps, RGB, state/action, целостность файлов,
неизменность источника во время экспорта и строит официальный LeRobot dataset.
Готовый export повторно открывается loader-ом LeRobot 0.6.1 и сверяется по
кадрам.

### 3.7. Обучение

`training_options.py` валидирует параметры и формирует split. По умолчанию
разделение выполняется целыми recording sessions, а не случайными кадрами:
эпизоды одного непрерывного сеанса не попадают одновременно в train и test.

`training.py` реализует ACT с нуля, SmolVLA из локального pretrained snapshot,
AMP, gradient accumulation, validation/evaluation, checkpoints с
optimizer/scheduler/RNG state, resume, pruning и lineage с хэшами.

Изображения проходят centered letterbox до квадратного входа, сохраняя
соотношение сторон. Это существенно: растяжение 640×480 до 256×256 меняет
геометрию сцены.

### 3.8. Очередь и MLflow

`jobs.py` запускает worker-процесс и сохраняет progress/result независимо от
браузерной вкладки. `ResourceLease` защищает dataset и аппаратные ресурсы.

`telemetry.py` отправляет параметры, метрики и artifacts в локальный MLflow. При
недоступности сервера события атомарно остаются в `runtime/mlflow-spool`; timer
повторяет доставку. Закрытие вкладки обучение не останавливает.

### 3.9. Inference

Есть два этапа: проверка модели/задержки без USB и torque, затем отдельный
физический Start. Для официального LeRobot rollout:

- fps сериализуется как integer;
- локальный plugin регистрируется как Python package;
- ACT checkpoint получает тот же centered-letterbox processor, что при train;
- стартовая поза вычисляется как медиана начала train-эпизодов;
- trace пишет actions, states и каждый десятый wrist-кадр, не меняя команды.

## 5. Выполненные этапы

### A. Независимая лаборатория

- создан отдельный проект, venv, lock-файл и user services;
- исключены импорты и запись в соседние worktree;
- сервер сделан hardware-cold при старте;
- добавлены preflight, inventory устройств и resource locks.

### B. Запись демонстраций

- подключены camera-only preview и отдельная телеоперация;
- восстановлено штатное calibrated leader following;
- добавлены raw state/action/timestamps и архив;
- реализованы STOP, quarantine, re-record, продолжение до общей цели и удаление;
- wrist-only UI очищен от top-камеры.

### C. Надёжность 30 FPS

- найдено переполнение writer во время синхронного `fsync`;
- найден kernel writeback из-за несжатых PNG;
- `fsync` перенесён на завершение, включено lossless compression 1;
- увеличена bounded queue, preview отделён от raw 30 FPS;
- STOP перестал помечать обрезанный эпизод как complete.

### D. Разметка, экспорт и обучение

- SAM3 привязан к точным raw-кадрам и вынесен из realtime;
- исправлена блокировка продолжения записи auto-SAM задачей;
- реализованы validation/finalize/export и проверка LeRobot loader;
- добавлены ACT/SmolVLA, session splits, resume и MLflow;
- собран и визуально проверен датасет из 50 wrist-only эпизодов;
- выполнены три полноразмерных обучения.

### E. Физический rollout

- исправлен `cameras.wrist.fps`: LeRobot принимает integer, не `30.0`;
- исправлена загрузка plugin как package с `__path__`;
- убран неподдерживаемый `--discover_packages_path`;
- найдено несовпадение preprocessing: train видел centered 256×256 letterbox,
  старый rollout — raw 480×640;
- processor зарегистрирован и добавлен в старые ACT manifests;
- добавлены start-pose synchronization и rollout trace;
- проверены варианты temporal ensembling из-за компромисса lag/jitter.

Официальные ACT rollout после исправлений завершались примерно за 13,2 секунды
и возвращали руку. Однако пользователь наблюдал промахи и отсутствие захвата.
Подтверждён запуск программного контура, но не успешное выполнение задачи.

## 6. Основные проблемы

| Проблема | Причина | Исправление | Остаток |
|---|---|---|---|
| Камеры «заняты» | второй владелец V4L | единый владелец и leases | внешний процесс освобождает устройство сам |
| Телеоперация замедлялась | лишний limiter/связь с camera path | штатное calibrated following | качество USB зависит от физического соединения |
| Запись обрывалась | `fsync` и PNG writeback | async writer, sync на границе, compression 1 | нужен свободный диск |
| STOP сохранял мусор | stop трактовался как complete | abort → quarantine | save остаётся отдельным действием |
| Нельзя продолжить датасет | auto-SAM держал lease | auto-SAM после достижения цели | ручная annotate job блокирует изменение датасета |
| LeRobot не стартовал | float fps, plugin discovery | integer fps, package plugin | привязка к LeRobot 0.6.1 |
| Рука промахивалась | train/runtime preprocessing и temporal behavior, затем ограниченное покрытие | одинаковый letterbox, trace, проверка ensemble | grasp не подтверждён |
| Цикл проседал | stalls inference/USB/системы | telemetry показывает провалы | причины кадров 5–6 Hz требуют профилирования |
| Exit 0 выглядел как успех | процесс не знает исход задачи | trace и кадры | нужна независимая success metric |

## 7. Что доказано и не доказано

Подтверждено:

- 50 реальных wrist-only эпизодов записаны;
- train/validation/test разделены по сессиям;
- ACT и SmolVLA обучились и сохранили checkpoints;
- MLflow принимает runs/artifacts;
- checkpoint загружается без движения;
- официальный LeRobot rollout отправляет actions и завершается;
- trace и wrist-кадры физического запуска сохраняются;
- UI/API не открывает аппаратуру при старте;
- STOP, quarantine и resource ownership реализованы.

Не подтверждено:

- успешный автономный захват текущей обученной политикой;
- обобщение на новые положения, коробки, освещение и предметы;
- универсальная сортировка или произвольная текстовая команда;
- достаточность 50 эпизодов для требуемой надёжности;
- метрическая 3D-геометрия только по wrist RGB.

## 8. Следующий измеримый цикл

1. взять неуспешный rollout trace;
2. сопоставить live wrist-кадры с train-кадрами по фазе и позе;
3. определить первую точку расхождения: обнаружение, подход, gripper, перенос;
4. проверить frequency/latency в этой точке;
5. если observation вне train — дозаписать целевые демонстрации;
6. если observation покрыто, а action неверна — проверить processors,
   chunk/ensemble и normalization;
7. оценивать checkpoint серией попыток и success metric, не exit code.

Отдельный запланированный эксперимент — переобучить ACT и SmolVLA на всех 50
эпизодах без holdout с включённой image augmentation. Такой run использует на
28% больше train-эпизодов, но не даёт независимой validation/test-оценки; его
следует считать deploy-кандидатом, сравнивая физически с моделями 36/9/5.
