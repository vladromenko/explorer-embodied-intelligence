# 03 · SO-101 leader → ROSMASTER

Геометрический путь находится в `shared/explorer_shared/kinematics.py`: именованные URDF-цепи, FK, ограниченный численный IK, привязка к предмету и clutch/recenter. Совпадение количества суставов не является соответствием суставов.

`ClutchRetargeter.recenter(source_q, target_q)` сохраняет текущие опорные позы. Обновление с `clutch=True` только меняет опоры и не выдаёт решение движения. После отпускания переносится относительное изменение позы; IK проверяет достижимость. Его результат — геометрическое предложение, а не команда исполнительному устройству.

SO-101 использует пять суставов цепи `base_link → gripper_frame_link`. Геометрия ведущей руки доступна в официальном `so101_leader_new_calib.urdf`; arm-цепь совпадает с follower, но триггер лидера имеет лишь предварительные CAD-пределы. Переход от физических отсчётов к этим радианам требует реальной калибровки конкретного устройства.

Для реального применения нужны измеренные системы координат, сохранённые IDs калибровок обеих рук, направление/ноль каждого привода и отдельное соответствие раскрытия захвата. `map_aperture` требует явные измеренные конечные точки и ID калибровки. Модельный URDF-gripper не соответствует напрямую LeRobot `0=закрыт, 100=открыт`.

Профили `ARM_ONLY` и `MOBILE_MANIPULATION` различаются источником команд шасси. Настоящий низколатентный маршрут Pi → Nano, существующий исполнитель и локальные сроки команд подключаются интегратором. Этот модуль не открывает serial, не публикует ROS, не меняет контроллер и не выдаёт виртуальные калибровки за физические.
